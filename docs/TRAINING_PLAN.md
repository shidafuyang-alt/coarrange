# MusicCraft 训练与实验建议

## 当前阶段

先完成预训练音乐模型推理和 Agent 提示词实验，不以训练作为上线前提。应先确定瓶颈来自意图解析、参数选择、音乐模型能力还是音频处理。训练通用 LLM 不会自动改善底层音乐模型的音质，也不会给 Cover 增加精确换声能力。

## 建议优先做的研究实验

固定底层模型版本、时长、输入片段、seed 集合和相同生成次数，比较：

1. 人工原始描述直接发送给音乐模型。
2. Planner 结构化规划后生成。
3. Planner 加上基于人工反馈的 Critic 建议，再修订。

第三组必须把初次生成和修订都计入预算；其他组获得相同次数。分别记录合法计划率、任务路由正确率、要求覆盖率、旧约束保持率、人工修正次数、耗时与调用成本。用随机顺序盲听比较风格、旋律可辨识程度与音质，不将 Critic 的文字当作听测分数。

先手工整理 30–50 条代表性指令作为开发集和独立测试集，覆盖中英文、含糊指令、多轮修改、约束冲突及超出工具能力的要求。这是建议的启动规模，不是训练所需数据量或效果保证。不要把 few-shot 示例直接当测试集。

## 什么时候考虑训练 Agent

如果多轮提示词改进后，仍稳定出现漏约束、工具选错或 JSON 格式问题，再考虑对开源文本模型做 LoRA／SFT。数据应包括：用户要求、可用工具与上下文、人工审核后的完整计划、被拒绝请求及原因、多轮修改前后版本。先积累数百条经过审校且覆盖不同情形的数据，再根据学习曲线决定是否扩充；少量重复或自动生成的相似样本不能代替覆盖面。

按任务来源／对话分组划分训练、验证、测试，避免同一对话的不同轮次跨集合。基线至少包含原模型零样本、few-shot 和微调模型。先离线评测计划，不必为每条样本运行昂贵的音乐生成。当前没有提供微调脚本，避免在未选定模型、许可证和数据之前固定训练栈。

## 什么时候考虑音乐 LoRA

如果主要问题是某个明确风格／乐器始终表现不好，才考虑音乐模型的风格 LoRA。先选一个窄目标，例如某类室内乐配器，而不是同时训练所有风格。使用自有或明确允许训练的音频，标注乐器、风格、情绪、BPM、调性和歌词／纯音乐状态。

ACE-Step 官方提供 LoRA 训练流程；官方教程列出的硬件为最低 16 GB 显存、推荐 20 GB 以上，实际占用仍受片段长度和训练配置影响。教程的数据包括音频、对应歌词和 caption／BPM／调性等标注。请以你们固定版本的教程为准：

- [ACE-Step LoRA 官方教程](https://ace-step.github.io/ACE-Step-1.5/en/LoRA_Training_Tutorial)
- [GPU 配置说明](https://ace-step.github.io/ACE-Step-1.5/en/GPU_COMPATIBILITY)

训练／验证／测试按原始歌曲划分，不把同一首歌的相邻片段分到不同集合。比较同一基础模型关闭和启用 LoRA 的结果，既测目标风格，也测原有通用能力与旋律保持的变化。小数据 LoRA 可能记忆训练歌曲；训练损失下降不能证明音乐变好。

官方训练示例中的歌曲数量和 epoch 只是示范，不是你们的推荐超参数。先用少量授权数据验证预处理和一次短训练是否能正常跑通，再依据验证集选择配置。项目目前没有安装训练环境、下载模型或启动训练。

## 换声能力的边界

用上传声音替换歌曲人声，需要专用歌声转换工具和人声分离／混音链路。风格 LoRA 不等同于个人声线克隆。可以先评估支持参考音频的零样本转换，再根据真实效果判断是否值得训练个人音色；不要把本轮 ACE-Step 的 Cover 上传入口当成换声接口。
